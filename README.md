## Development Philosophy

I don't want to learn programming by memorising what each technology does.

I want to understand **why things work**.

When I encounter something unfamiliar, my first instinct is usually to take it apart and see what happens.

That means I tend to learn by:

* Building things
* Breaking things
* Reading documentation
* Experimenting
* Trying approaches that may not work
* Figuring out why they didn't work
* Building them again

The code gets better with time.

So does the developer writing it.
